# Restart-safe runs and MCP secrets off argv Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bridge restart never mislabels or strands a turn: a Claude child the stop took down is left for boot recovery and never reads CRASHED. No MCP token ever sits on a process's command line.

**Architecture:** Restarts are fixed at three layers. The unit signals the bridge alone (`KillMode=mixed`), and the bridge stops its own children after raising `state.shutting_down`. The runner treats a stop-signal exit as the restart, waiting a short grace for the flag, and journals no error for it. `outcomes` reads an error turn with no `elapsed`, which only the boot-time orphan flip leaves, as `restarted`. For the secrets, `runner._mcp_config` writes a 0600 file in a fresh 0700 temp dir and returns its path, and `_run_streaming` removes that dir once the child is reaped.

**Tech Stack:** Python 3 stdlib only (3.14 on this machine); pytest; a systemd user unit generated by `bridge/startup.py`; Claude Code CLI 2.1.280.

**Spec:** `/home/mhzrerfani/projects/mystical-assistant/.mystical/docs/reports/Mystical Assistant feature opportunities.md`, section "Seven bridge upgrades", item 1 (restart-safe runs). Fix 2 (MCP secrets) has no written spec. Its brief is restated at the top of Task 4.

## Decisions the spec left open

1. **No error event for a stop-killed child.** New restart casualties then read INTERRUPTED, which both UIs paint as good news with ◇ (`Transcript.tsx:84`, `run.tsx:446`). That is "recorded as interrupted by restart" in the spec's words.
2. **`_stopping(rc)`.** Stop-signal exits are 143/-15 (SIGTERM) and 130/-2 (SIGINT, from Ctrl-C under `mystical run` or `mystical stop`'s group signal). `STOP_GRACE = 3.0` s, and only those exits wait. -9 (the OOM killer) and every other exit are decided at once. A real SIGTERM while the bridge stays up waits 3 s before it is recorded and auto-resumed.
3. **The bridge stops its own children in `_shutdown()`, right after the flag.** This generalises selfupdate's pattern. `KillMode=mixed` needs it for a graceful SIGTERM, and it fixes the re-exec leak in point 7.
4. **TimeoutStopSec stays at the 90 s default.** A stop takes about 1 s, and `stop_children` allows 10 s per child that ignores SIGTERM. Expiry only SIGKILLs everything, which still leaves turns `running` for recovery. `KillMode=mixed` also ends the two 90 s `final-sigterm` waits, because leftovers get SIGKILL the moment the bridge exits. The tradeoff is that anything the bridge doesn't stop itself (dashboard SHELL commands, a tool's background process) gets SIGKILL at a restart instead of SIGTERM.
5. **`outcomes` keys on `elapsed IS NULL`, not on the exit string.** On a boot-flipped row, any message that matches none of the specific causes (timeout, limit, auth and so on) reads `restarted`. That covers 143, stderr tails, and the bot path's result string. 143 with `elapsed` set stays `crashed`. After Task 1 the runner finishes a stop-signal death itself only when the bridge stayed up, so that row is a real kill. Before Task 1 such a row is ambiguous (race or real kill), and `crashed` is the safer default: RESTARTED would suggest recovery handled a turn it never saw. The code is `restarted` as the spec asks, but it renders red ✕ while new casualties render ◇ INTERRUPTED. If history should match, change the one word in Task 3 Step 3.
6. **The MCP file is per run.** It is `mcp.json` (0600, `O_EXCL`) in a fresh `tempfile.mkdtemp(prefix="mystical-mcp-")` dir (0700), created inside `_mcp_config`, so `_base_cmd`'s signature doesn't change. `_run_streaming` reads the dir off its own `_base_cmd` output before `job.extra_args` is appended, so a user-supplied `--mcp-config` can never be the one deleted. It removes the dir in `finally`, right after the child is reaped. The file lives as long as the child because the CLI may re-read it on a reconnect. That is unverified, and deleting the file after start-up would silently drop tools if it does. Concurrent runs can't clobber each other because each has its own dir. It goes in `/tmp`, not `~/.bridge_state`, because boot wipes a hard-killed bridge's leftovers there and tests never touch the state dir.

```python
def _child(rc, stderr=""):
    """A claude that prints nothing on stdout and exits `rc`."""
    class Child:
        def __init__(self, cmd, **kw):
            self.stdin, self.stdout = io.StringIO(), io.StringIO("")
            self.stderr = io.StringIO(stderr)
            self.returncode = rc

        def poll(self):
            return self.returncode

        def wait(self, timeout=None):
            return self.returncode

        def kill(self):
            pass
    return Child
```

```python
# How a child dies of a stop signal: SIGTERM (systemd stopping the unit, or
# stop_children) or SIGINT (Ctrl-C, `mystical stop` signalling the process
# group) — raw as -N, or as the CLI's own 128+N exit once it handled the signal.
_STOP_EXITS = (-15, 143, -2, 130)
# How long a child that died of one waits for the bridge to say it is stopping.
STOP_GRACE = 3.0


def _stopping(rc: "int | None") -> bool:
    """Is the bridge going down with this child? The stop signal can reach both
    at once, and Python runs the bridge's handler on the main thread only, so a
    runner thread can see its child die before shutting_down is up. A death by a
    stop signal waits up to STOP_GRACE for the flag; any other exit doesn't."""
    # ponytail: polls a bool every 50 ms for at most STOP_GRACE. An Event would
    # wake at once; this only runs for a child that died of a stop signal.
    end = time.time() + (STOP_GRACE if rc in _STOP_EXITS else 0)
    while not state.shutting_down and time.time() < end:
        time.sleep(0.05)
    return state.shutting_down
```

```python
    external servers this session left switched on. PYTHONPATH pins the repo root
```

# Easy setup + onboarding wizard

Getting mystical-assistant running today is a six-hurdle gauntlet, and two of the
hurdles are hard stops that a new user cannot clear without reading source. This
is the single biggest barrier to the "find early real users" goal: the value is
highly showable, but a curious developer who lands on the repo hits a wall at
install and never reaches the first turn. This spec makes first-run
**`git clone` → `./setup.sh` → message your bot**, under five minutes, no build
step, no blank-file authoring.

Goal restated as a success criterion: a developer who has `claude` installed and
logged in, and who has never seen this repo, gets a working bot + dashboard by
running one script and answering its prompts — without opening an editor or
reading `config.py`.

## What already exists (verified)

- **`run.sh` is git-ignored and has no template.** `git ls-files` matches no
  `run.sh`, `.env`, or `*.example`. `bin/mystical:42` hard-exits with
  `"run.sh not found … create it before starting."` The user is expected to
  author, from nothing, a bash script that exports the right env vars and
  launches python. Nothing tells them what those vars are. **Hard block #1.**
- **Config is env-driven** (`bridge/config.py`). Required-ish: `TELEGRAM_BOT_TOKEN`
  (`:6`), `BASE_PATH` (`:10`, defaults to cwd), `ALLOWED_CHAT_IDS` (`:16`). Almost
  everything else has a sane default. `DASH_TOKEN` is a fresh random per run
  unless set (`:111-112`). The `FOO = os.environ.get("FOO", default)` /
  boolean-via-`not in ("0","false",…)` idiom is uniform.
- **Author-specific defaults are baked in.** `config.py:73-79` defaults
  `PREVIEW_HOSTNAME=preview.mhzrerfani.dev`, `TUNNEL_NAME=mystical-preview`,
  `TUNNEL_ID=612b1ee2-…`, and tunnel cred/config paths — i.e. *the maintainer's*
  tunnel account. A new user's `/preview` targets someone else's tunnel out of
  the box. **Correctness bug for anyone but the author.**
- **Discovery mode exists** for chat-id capture. Empty `ALLOWED_CHAT_IDS` →
  `dispatch.py:45-51` prints `[discovery] chat_id=… — add to ALLOWED_CHAT_IDS`
  and `claude_telegram_bridge.py:111-112` warns it won't execute. Works, but
  requires the user to *read the log* to find their id, edit config, and restart.
- **Both web clients must be built; `dist/` is git-ignored.** `git check-ignore`
  confirms `bridge/miniapp/web/dist` and `bridge/dashboard/web/dist` are both
  ignored — there is no prebuilt fallback. Build script for each is
  `tsc -b && vite build`. **Hard block #2.**
- **The two clients use different package managers.** `bridge/miniapp/web` ships a
  `package-lock.json` (npm). `bridge/dashboard/web` ships **both** a
  `package-lock.json` *and* a `pnpm-lock.yaml` + `pnpm-workspace.yaml`. The README
  tells everyone to use npm; project memory records that `pnpm build` trips on
  esbuild. The build path is inconsistent and fragile.
- **`bin/mystical`** is a committed, secret-free launcher
  (start/stop/restart/status/logs/run). It `source`s nothing itself — it just
  execs `run.sh` and greps `DASH_PORT`/`DASH_TOKEN` out of it for the status URL
  (`:58-62`). Installed manually via `ln -sf … ~/.local/bin/mystical` (`:9`).
- **the tunnel client is effectively mandatory.** Needed for the Mini App's ephemeral
  quick tunnel and for `/preview`. A user who only wants the localhost dashboard
  still can't cleanly avoid it today.

## The end-state flow (happy path)

```
git clone …/mystical-assistant && cd mystical-assistant
./setup.sh
  ✓ claude found & logged in   ✓ python3 3.11   ✓ node 22 (for optional rebuild)
  → Create a bot: open @BotFather → /newbot → paste the token here: ••••
  ✓ token saved to .env
  → Now open Telegram and send your bot any message… (waiting)
  ✓ captured chat id 12345678 — you're the only allowed user
  → Enable the Telegram Mini App control panel? (needs a tunnel client) [y/N]: n
  ✓ wrote .env   ✓ linked `mystical` onto your PATH
Start it:  mystical
Dashboard: http://127.0.0.1:8790/?token=…
```

## 1. Config via `.env`, not a hand-written script

Split secrets/overrides out of `run.sh` into a git-ignored **`.env`**, and
**commit `run.sh`** (it holds no secrets). This deletes hard block #1.

- **New `run.sh` (committed):** loads `.env` and launches the bridge —
  `set -a; . "$(dirname "$0")/.env"; set +a; exec python3 claude_telegram_bridge.py`.
  Remove `run.sh` from `.gitignore`; add `.env` to it.
- **New `.env.example` (committed):** the authoritative, commented template.
  Required vars up top (`TELEGRAM_BOT_TOKEN`, `BASE_PATH`, `ALLOWED_CHAT_IDS`),
  each with a one-line comment; everything else grouped below under
  `# --- optional ---` with its default shown. Generated by hand to mirror
  `config.py`, and kept honest by a tiny test (§7).
- **`bin/mystical` status URL:** it currently greps `DASH_TOKEN`/`DASH_PORT` from
  `run.sh` (`:58-62`). Point that at `.env` instead (the values move there).

## 2. Ship prebuilt web assets + standardize the toolchain

Deletes hard block #2.

- **Commit `dist/` for both clients.** Un-ignore `bridge/miniapp/web/dist` and
  `bridge/dashboard/web/dist` so a fresh clone is immediately runnable with no
  Node and no build. (Decision — see Open decisions; the alternative is shipping
  them as GitHub Release assets that `setup.sh` downloads.)
- **Standardize on npm.** Delete the dashboard's `pnpm-lock.yaml` and
  `pnpm-workspace.yaml`; keep its `package-lock.json`. Verify
  `npm ci && npm run build` produces a clean `dist` for the dashboard (the memory
  note about esbuild is a pnpm artifact; npm is the supported path). README and
  wizard reference npm only.
- **`setup.sh --build` / `mystical build`** rebuilds both from source for users
  who change the frontend; the committed `dist/` is the default and the happy
  path never needs it.

## 3. Remove author-specific defaults (`config.py:73-79`)

- Default `PREVIEW_HOSTNAME`, `TUNNEL_NAME`, `TUNNEL_ID`,
  `TUNNEL_CREDENTIALS_FILE`, `TUNNEL_CONFIG_FILE` to **empty/None**.
- **`/preview` degrades gracefully:** when no named tunnel is configured, fall
  back to an ephemeral throwaway-hostname quick tunnel (the same primitive the
  Mini App already uses via `tunnel.open_quick_tunnel`) instead of pointing at a
  stranger's hostname. A named, stable tunnel becomes an opt-in documented in
  `.env.example`, not a baked-in default.

## 4. `setup.sh` — the interactive wizard

A single committed bash script, idempotent (safe to re-run; it reads existing
`.env` and only asks for what's missing).

1. **Prereq doctor.** Check `claude` (and that it's logged in — e.g. a cheap
   `claude` invocation or presence of its creds), `python3` (≥3.9) + `requests`,
   `curl`, `jq` (or fall back to a python one-liner for JSON), and — only if the
   user opts into the Mini App/preview — the tunnel client, `node`/`npm`. Print each
   result and an install hint for anything missing; hard-fail only on the truly
   required ones (`claude`, `python3`).
2. **Bot token.** If absent from `.env`, print the 3-step @BotFather walkthrough
   inline and read the pasted token (no echo). Write it to `.env`.
3. **Chat-id auto-capture.** Instead of the log-reading dance: prompt "message
   your bot now", then poll `getUpdates` on the token until a message arrives,
   extract `message.chat.id`, and write it to `ALLOWED_CHAT_IDS`. Confirms the
   token actually works as a side effect.
4. **Mini App toggle.** Ask whether to enable the Mini App panel (needs
   the tunnel client). If no, set `MINIAPP_ENABLE=0` — the bot + dashboard run with
   the tunnel client entirely absent.
5. **Assets.** Use the committed `dist/`. Only build if `--build` was passed or a
   `dist/` is somehow missing.
6. **Install `mystical`.** `ln -sf "$PWD/bin/mystical" ~/.local/bin/mystical`
   (create the dir; warn if `~/.local/bin` isn't on `PATH`, with the export line
   to add).
7. **Finish.** Print `mystical` to start and the dashboard URL.

## 5. `mystical doctor` (small, optional)

Factor the §4.1 prereq checks into `bin/mystical doctor` so an already-set-up
user can re-diagnose ("why won't the Mini App tunnel come up?") without re-running
setup. Thin wrapper over the same checks; no new logic.

## 7. Tests

Backend-only, stdlib `unittest`, matching `tests/test_*.py`:

- **`.env.example` ↔ `config.py` drift test.** Parse the var names out of
  `.env.example` and assert every one is read in `config.py`, and that the three
  required vars are present in the example. Cheap guard so the template can't rot.
- **Preview fallback.** With `PREVIEW_HOSTNAME`/`TUNNEL_ID` empty, assert the
  preview path chooses the quick-tunnel branch rather than a named tunnel.
- `setup.sh` itself is not unit-tested (interactive bash); its logic is kept thin
  and its pieces (chat-id capture = one `getUpdates` call) are individually
  observable.

## Scope explicitly excluded

- **No Docker/compose image, no hosted/managed option.** Self-hosted only, as
  today. Can layer later if setup-in-a-container is demanded.
- **No systemd/launchd service install.** `mystical` background mode is enough.
- **No auto-install of `claude`, the tunnel client, or Node.** The doctor points at
  install docs; it does not run package managers on the user's behalf.
- **No GUI/onboarding inside the Mini App or dashboard.** Setup is terminal-only.
- **No multi-user / team onboarding.** Single-owner model (`ALLOWED_CHAT_IDS`
  locked to you) is unchanged.

## Open decisions (for review)

1. **Prebuilt assets: commit `dist/` vs. GitHub Release assets.** Spec assumes
   **commit `dist/`** — simplest, offline, clone-and-run, no release infra for a
   solo maintainer; cost is repo bloat and remembering to rebuild before
   committing frontend changes. Precedent: the repo already commits a built
   artifact on purpose (`tools/selector-plugin/dist/agent.global.js`,
   `.gitignore:24-25`). If bloat bites, switch to Release assets that
   `setup.sh` downloads. Reversible.
2. **npm vs. fixing pnpm.** Spec drops pnpm and standardizes on npm. If you
   actually want the pnpm workspace, the alternative is fixing the esbuild issue
   and standardizing on pnpm instead — but npm is the lower-friction default.
